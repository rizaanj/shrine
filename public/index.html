🛡️ Shrine Security Scanner

CLI tool to scan repositories for exposed secrets, API keys, and security misconfigurations

Shrine detects hardcoded secrets, JWT tokens, database credentials, and API keys in your codebase. It scans working directories, git history (including force-pushed commits), and Supabase RLS/storage configurations. Currently in beta with free access.

Quick Start Guide

1
Install the CLI npm install -g shrine-cli
2
Authenticate with your access key shrine login <your-access-key>
3
Run a security scan shrine scan

Available Commands

shrine login <access-key>
Authenticate with your Shrine access key and save it locally
shrine logout
Remove your stored access key from local configuration
shrine scan
Scan current directory for exposed secrets and API keys
shrine scan --path <dir>
Scan a specific directory for secrets
shrine scan --history
Scan git commit history for secrets (default: 100 commits)
shrine scan --deep-history
Scan reflog and orphaned commits for secrets hidden by force-pushes
shrine scan --supabase
Scan Supabase database for RLS and storage misconfigurations
shrine scan --entropy
Enable entropy-based detection for unknown secret patterns
shrine scan --verbose
Enable detailed output showing scan progress and file paths
shrine scan --fix-prompts
Generate AI-ready fix prompts for each finding (batched by vulnerability type)

✓ What Shrine Detects

  • API keys (AWS, Stripe, OpenAI, GitHub, etc.)
  • Database connection strings
  • JWT tokens and auth credentials
  • Committed .env files and secrets
  • Git history secrets (including reflog)
  • Supabase RLS misconfigurations
  • AST-based detection for JS/TS
  • Entropy-based unknown pattern detection

⚠ Beta Limitations

  • Beta access required (free)
  • Network validation on every scan
  • Limited to supported secret patterns
  • English language output only
  • CLI-only (no web dashboard)
  • No automated remediation
  • Community support only
